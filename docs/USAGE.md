# 使用手册

本文是 ScreenRecorder 的完整使用说明，涵盖界面每一项、命令行全部参数、输出规格与故障排查。只想快点录一段的话，看 [README 的「快速开始」](../README.md#快速开始) 就够了。

---

## 1. 两种用法

| 形态 | 适用场景 | 需要 Python | 需要 FFmpeg |
| --- | --- | --- | --- |
| 免安装包 `ScreenRecorder-win64-portable.zip` | 日常使用、给别人用 | 否 | 否（已内置 79 MB 的 `ffmpeg.exe`） |
| 源码 `screen_recorder.py` | 改代码、二次开发 | 是（3.9+，自带 tkinter） | 是（需本机有 ffmpeg） |

免安装包解压后结构：

```
ScreenRecorder/
  ScreenRecorder.exe     双击启动
  ffmpeg.exe             内置录制内核，别删
  _internal/             Python 运行时 + Tcl/Tk，别删
  使用说明.txt
```

**整个文件夹必须一起移动或复制。** 只把 `ScreenRecorder.exe` 拿出来单独放，会因为找不到 `_internal` 而启动失败。

第一次运行 Windows 可能弹 SmartScreen（未签名的可执行文件都会），点「更多信息 → 仍要运行」。觉得每次弹很烦，可以右键 exe → 属性 → 勾选「解除锁定」。

## 2. 界面说明

启动后窗口标题是「本地录屏 · ScreenRecorder」，标题下方一行灰字显示当前 FFmpeg 的版本与路径来源，用来确认到底在用哪一个 ffmpeg。

### 2.1 区域

三种模式，切换方式不同：

| 选项 | 行为 |
| --- | --- |
| 整个桌面（所有显示器） | 按虚拟桌面尺寸采集，多显示器一次性全录进去 |
| 主显示器 | 只录主屏，尺寸取 `GetSystemMetrics` 的物理像素 |
| 自定义区域 | 点「框选区域…」进入框选模式 |

**框选操作**：点击后整个屏幕会盖一层半透明遮罩，鼠标变成十字，按住左键拖出矩形，松开即确认；按 `Esc` 取消。框选结果会显示成 `x,y 宽×高`。

框选用的是全屏 `Toplevel` + `Canvas`，坐标系已经过 DPI 处理，所以在 125% / 150% 缩放的屏幕上框出来的区域和最终视频的像素边界一致 —— 实测录 `0,0,400,400` 与全屏帧裁剪同区域对比，SSIM 为 0.999996。

> 注意：FFmpeg `gdigrab` 的偏移量不能为负。副屏在主屏左侧或上方（虚拟坐标为负）时，框选会被限制在主屏范围。副屏在主屏右侧的横向拼接不受影响，「整个桌面」模式也不受影响。

### 2.2 帧率

15 / 24 / 30 / 60，默认 30。

- 录聊天、演示、代码：30 足够
- 录游戏、动画：60 更跟手，但 CPU 或硬件编码压力翻倍
- 长时间录、只想留证据：15 也能用，文件小很多

帧率是写入容器的**恒定帧率**，采集端掉帧时由 FFmpeg 补帧，不会出现「录了 10 秒、播放只有 7 秒」的情况。

### 2.3 画质

对应 libx264 的 CRF 值：

| 选项 | CRF | 1080p30 大致码率 | 适用 |
| --- | --- | --- | --- |
| 高质量（体积大） | 18 | 3～6 Mbps | 素材要再剪辑 |
| 标准（推荐） | 20 | 2～4 Mbps | 日常存档、分享 |
| 较小体积 | 24 | 1～2 Mbps | 长会议、教程 |
| 最小体积 | 28 | 0.5～1 Mbps | 只求看得清内容 |

用硬件编码（QSV / NVENC / AMF）时，这一项会换算成对应的 `-global_quality`，语义相同。

### 2.4 编码

| 选项 | 说明 |
| --- | --- |
| `libx264`（软件编码，兼容最好） | 任何机器都能用，画质/体积比最优，吃 CPU |
| `h264_qsv`（Intel 硬件加速） | Intel 核显专用，CPU 占用极低 |
| `h264_nvenc`（NVIDIA 硬件加速） | N 卡专用 |
| `h264_amf`（AMD 硬件加速） | A 卡专用 |

程序启动时会对候选编码器**真跑一次编码测试**（不是看 `-encoders` 列表），跑不过就不显示。所以列表里没有 QSV 说明你的驱动或核显确实不支持，不是程序漏了。

启动时这一项先只有 `libx264`，后台探测完成后才补上硬件编码项 —— 下拉框当前值不会自己变，展开才能看到新增项。

### 2.5 麦克风

默认「不录音（仅画面）」。选具体设备名就会把麦克风混进 MP4。

设备名来自 FFmpeg 的 DirectShow 枚举，格式通常是 `麦克风阵列 (适用于数字麦克风的英特尔® 智音技术)` 这种完整名字。用命令行时 `--audio` 要传一模一样的字符串，先跑一次 `--list-devices` 抄下来最省事。

### 2.6 勾选项

- **录制鼠标指针**：勾上则光标画进视频。录教程、演示操作时勾上；录视频画面时通常关掉。
- **完成后打开文件夹**：录制结束自动用资源管理器打开输出目录。

### 2.7 保存位置

默认 `%USERPROFILE%\Videos\录屏`（首次使用自动创建）。可以点「浏览…」换目录。

文件名自动生成 `录屏_YYYYMMDD_HHMMSS.mp4`，秒级时间戳，不会覆盖。想指定文件名就用命令行 `-o`。

## 3. 录制流程

1. 点「开始录制」→ 按钮变成「取消」，状态显示「3 秒后开始录制…」，倒计时 3 秒给你切到要录的内容
2. 倒计时结束，主窗口自动收成右下角 400×185 的小控制条（置顶），显示「正在录制」、实时计时和当前 fps
3. 小控制条上点「停止录制」，或直接按 `Esc`
4. 状态变为「正在封装 MP4…」，完成后显示「已保存：文件名」，并给出时长、分辨率、文件大小

小控制条设计成贴右下角，就是为了尽量不遮挡被录内容。如果你的工作区在右侧，录制前可以先把小控制条拖走。

**录制中关窗口**不会直接丢弃：会弹确认框，选「是」则优雅停止并保存（可能等几秒封装）。这样不会留下孤儿 ffmpeg 进程和半截文件。

**录制中误按取消**：倒计时阶段按「取消」不会产生文件；已经进入录制阶段后按钮是「停止录制」，只会在当前已录内容上收尾。

## 4. 输出规格

| 项目 | 值 |
| --- | --- |
| 容器 | MP4，`-movflags +faststart`（索引前置） |
| 视频编码 | H.264，`yuv420p`（兼容性最好的像素格式） |
| 帧率 | 恒定，按界面选择（15/24/30/60） |
| GOP | `-g fps*2`，即 30fps 时关键帧间隔约 2 秒，拖动进度条更顺 |
| 音频 | AAC，48 kHz，立体声，160 kbps（仅选了麦克风时） |
| 校验 | 停止后自动用 `ffprobe -print_format json` 读回文件，确认容器完整、时长正确 |

用 `ffprobe` 自己复核：

```bat
ffprobe -hide_banner -print_format json -show_format -show_streams "录屏_20261118_170730.mp4"
```

## 5. 命令行用法

### 5.1 基本形式

```bat
python screen_recorder.py --cli [参数]
```

`--cli` 表示不打开界面。不加 `--duration` 会一直录到按 `Ctrl+C`，此时同样走「写 `q` 收尾」的路径，文件是完整的。

### 5.2 参数详解

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--cli` | 开关 | 关 | 命令行录制模式 |
| `-o, --output` | 路径 | `%USERPROFILE%\Videos\录屏\录屏_时间戳.mp4` | 省略扩展名会自动补 `.mp4`；父目录不存在会自动创建 |
| `--fps` | 15/24/30/60 | 30 | 帧率 |
| `--region` | `x,y,w,h` | 整个桌面 | 物理像素坐标，`0,0` 是虚拟桌面原点 |
| `--audio` | 设备名 | 不录音 | 必须和 `--list-devices` 输出的名字完全一致 |
| `--encoder` | 编码器名 | `libx264` | `libx264` / `h264_qsv` / `h264_nvenc` / `h264_amf` |
| `--crf` | 18～28 | 20 | 数值越小画质越好、文件越大 |
| `--duration` | 秒 | 无（等 Ctrl+C） | 到点自动停 |
| `--no-mouse` | 开关 | 录指针 | 不把光标画进视频 |
| `--ffmpeg` | 路径 | 自动探测 | 指定 `ffmpeg.exe` |
| `--list-devices` | 开关 | — | 打印麦克风设备与编码器可用性后退出 |
| `--list-screens` | 开关 | — | 打印显示器与虚拟桌面几何后退出 |
| `--smoke` | 开关 | — | 只构建一次界面然后退出，用于自检环境 |

### 5.3 常见组合

```bat
:: 录 10 秒整屏，30fps，标准画质
python screen_recorder.py --cli --duration 10 -o demo.mp4

:: 只录左上角 800×600 一块
python screen_recorder.py --cli --region 0,0,800,600 -o area.mp4

:: 带麦克风录音
python screen_recorder.py --cli --audio "麦克风阵列 (适用于数字麦克风的英特尔® 智音技术)" --duration 30 -o voice.mp4

:: 60fps + 硬件编码录游戏
python screen_recorder.py --cli --encoder h264_qsv --fps 60 --crf 24 -o game.mp4

:: 不录鼠标指针
python screen_recorder.py --cli --no-mouse --duration 15 -o clean.mp4

:: 先看看这台机器有什么设备
python screen_recorder.py --list-devices
python screen_recorder.py --list-screens
```

`--list-devices` 的输出形如：

```
FFmpeg: 6.1.1-essentials_build  (C:\tools\ffmpeg.exe)
麦克风设备:
  - 麦克风阵列 (适用于数字麦克风的英特尔® 智音技术)
编码器:
  - libx264            可用
  - h264_qsv           可用
  - h264_nvenc         不可用
  - h264_amf           不可用
```

### 5.4 免安装包里的命令行

`ScreenRecorder.exe` 是窗口版，同样接受 `--cli`，文件会正常产出，只是没有控制台窗口，看不到实时日志。需要看日志就用源码方式跑，或自行按 [BUILD.md](BUILD.md) 打一个控制台版。

## 6. 故障排查

### 录出来是黑屏 / 全黑

独占全屏（Exclusive Fullscreen）的游戏、部分远程桌面会话、受 DRM 保护的播放器，GDI 层拿不到画面。

- 游戏改成「无边框窗口 / 窗口化全屏」
- 远程桌面改用本地机器录制
- 视频网站 DRM 内容无法录制，这是设计限制

### 帧率跑不满（30fps 只有 20 上下）

1. 看是不是开了硬件编码：`--encoder h264_qsv` 或界面里选 QSV，CPU 占用会掉一个数量级
2. 4K 屏 + 软件编码基本都会掉帧，把帧率降到 30 或 24
3. 带麦克风时如果掉帧，程序已加 `-thread_queue_size 512` 缓解，仍不行就换 USB 麦克风（板载阵列驱动有时会阻塞）

### 硬件编码选项不见了

程序是真跑一次编码测试才列出来的。没有说明驱动不支持：

- Intel 核显：更新显卡驱动；部分老核显（如 HD 4000 之前）不支持 QSV H.264
- NVIDIA：需要驱动支持 NVENC，GTX 600 之前的老卡没有
- AMD：需要 AMF 支持

更新驱动后重开程序即可。

### 找不到 FFmpeg（源码方式）

按这个顺序找：`--ffmpeg` 参数 → `SCREEN_RECORDER_FFMPEG` 环境变量 → 程序目录的 `ffmpeg.exe` → PATH → WinGet / 常见安装路径。

最快的办法：把 `ffmpeg.exe` 直接放到 `screen_recorder.py` 同目录。

### 双击没反应 / 启动就退出

源码方式下没有控制台，异常会写到同目录的 `screen_recorder_error.log` 并弹窗显示堆栈。免安装包方式下日志写在 `ScreenRecorder.exe` 同目录。

### 麦克风录进去没声音

- 确认设备名和 `--list-devices` 完全一致（含括号里的全角字符）
- Windows 设置 → 隐私 → 麦克风，确认「允许桌面应用访问麦克风」开着
- 检查输入音量：设置 → 系统 → 声音 → 输入

### 录制中关闭窗口会怎样

会弹确认框，选「是」则停止并保存当前已录内容（封装需要几秒，别急着杀进程）；选「否」继续录制。
